# 全量静态构建

站点默认走**全量静态**：所有页面在构建期一次性生成，运行时不再访问 Notion，
也不产生任何 ISR 写入。

## 为什么改成这样

原本用的是 ISR（页面按 `revalidate` 间隔自动再生）。它带来了两次真实事故：

### 1. Vercel 免费额度被打满（208K / 200K ISR 写入）

ISR 的写入量 = **有流量的页面数 × 每天再生次数**，和你发几篇文章无关。

| revalidate | 单个持续有流量的页面 | 每天写入 | 每月 |
|---|---|---|---|
| 60 秒 | 每分钟再生一次 | ~1,440 | ~43,200 |
| 3600 秒 | 每小时再生一次 | 24 | ~720 |

按 60 秒算，**只要 5 个页面被持续访问（含爬虫），一个月就是 216,000 次**，直接爆额度。

### 2. 首页变成空列表

ISR 会在**运行时**回源 Notion。Notion 一旦超时、限流或返回 403，
拿到的空数据就可能被生成成页面并缓存住——首页直接变空，而且额度耗尽时
连自愈都做不到（重新生成算得出新数据，但写不回缓存）。

## 全量静态怎么解决

```
构建期：拉一次 Notion → 生成全部页面 → 部署
运行时：只发静态文件，完全不碰 Notion
```

- **ISR 写入为零** —— 额度问题从根上消失
- **站点不会变空** —— Notion 拉不到数据时构建直接失败，
  Vercel 保留上一个成功的部署，线上继续正常服务旧内容
- **更快** —— 没有回源，所有页面都是纯静态命中

`pages/index.js` 里有一道硬保险：全量静态模式下如果首页文章列表为空，
**直接抛错中止构建**，绝不让空站点上线。

## 代价

**发文后不会自动上线，需要触发一次重新构建。**

三种触发方式：

1. **Vercel 后台**：Deployments → 最新那条右侧 `⋯` → Redeploy
2. **Deploy Hook**：Settings → Git → Deploy Hooks 建一个，然后
   ```bash
   curl -X POST "https://api.vercel.com/v1/integrations/deploy/xxx"
   ```
3. **定时**：GitHub Actions 定时调上面的 Deploy Hook（每天一次通常够用）

## 两个构建模式别搞混

| | 作用 | 服务端 |
|---|---|---|
| `FULL_STATIC`（默认开） | 全量预渲染 + 关闭 ISR | ✅ 保留，API 路由可用 |
| `EXPORT=true` | 真·静态导出（`output: 'export'`） | ❌ 无，API 路由和 SSR 页面全部失效 |

之前这两件事被 `isExport()` 一个开关捆在一起，导致「想去掉 ISR」就必须
连 API 路由一起砍掉。现在拆成了 `isExport()` / `isFullStatic()` 两个函数。

## 回退到 ISR

设环境变量 `FULL_STATIC=false`，此时 `NEXT_PUBLIC_REVALIDATE_SECOND`
（默认 3600）重新生效。

⚠️ 回退前先确认 Vercel 的 ISR 写入额度还够用。

## 构建失败时怎么查

构建日志里按顺序搜这几个关键词：

| 关键词 | 含义 |
|---|---|
| `NOTION_ACCESS_DENIED` | Notion 返回 401/403，权限问题。检查页面是否仍「分享到网络」、`NOTION_PAGE_ID` 是否正确 |
| `ALLPAGES_EMPTY` | Notion 通了但一篇文章都没解析出来 |
| `COLLECTION_SCHEMA_EMPTY` | 数据库 schema 拿不到，会导致所有文章丢失 slug/status 而被整批过滤 |
| `首页文章列表为空，中止构建` | 上面那道硬保险触发了 |

**构建失败不影响线上**——Vercel 只会在构建成功后才切换部署。
